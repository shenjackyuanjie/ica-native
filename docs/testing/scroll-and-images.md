# 滚动与图片加载测试

这些自动化测试验证图片几何、滚动输入、阅读锚点和异步加载失效规则。它们属于统一的 `cargo test` 目标，不是运行时自测，也不能度量 GPU 上传、显示器刷新率、真实网络延迟或主观滚动手感。

## 测试位置与隔离

- [滚动测试](../../src/app/chat/tests/scroll.rs)与[图片预览测试](../../src/app/chat/tests/image_preview.rs)仅在 `cfg(test)` 下编译，使用无窗口 egui、内存消息、假纹理和 `bytes://` 图片；不读取用户配置、不连接 Bridge、不访问真实聊天、不请求网络图片。
- [GIF 测试](../../src/image_loader/tests/gif.rs)、[纹理测试](../../src/image_loader/tests/texture.rs)和[静态加载器链测试](../../src/image_loader/tests/mod.rs)覆盖真实图片加载器实现。GIF 并发用例通过通道和队列标记控制解码开始、完成与失效；活跃性与淘汰用例直接控制缓存时间戳，不用耗时 GIF 或睡眠猜测结果。纹理用例还在真实中央聊天面板中检查图片网格，确认临时 Pending 时实际继续绘制可用帧。
- 全量测试与环境要求从[测试指南](README.md)进入；下面只列本专项的覆盖和执行方式。

## 自动化覆盖

| 场景 | 验收条件 |
| --- | --- |
| 正文、引用和窄窗图片槽 | Pending（有／无尺寸）、Ready、长短错误及模拟淘汰重载下高度保持不变；方图、横图、竖图和小图均不撑宽 |
| 首次下载与解码占位 | 持续 Pending、有／无尺寸提示及下载／解码切换时，旋转弧长度、线宽与颜色保持恒定；跨越周期零点仍可见，不缩成点 |
| 占位无障碍语义 | 下载及解码期间保留进度指示器角色，就绪或失败后由图片或错误内容替换；标记不改变父级预览布局 |
| 占位到首帧的过渡 | 首帧及帧时长元数据生效后直接画出图片，不空白、不叠加加载指示；后续失败立即显示错误，预览槽位置与大小不变 |
| 占位重绘节奏 | 稳定可见占位使用延迟重绘，不请求满速空转；裁剪外占位不绘制、不驱动动画重绘。加载完成的立即唤醒仍由加载器负责 |
| 连续图片状态变化 | 行高、后续消息 top、总内容高度和中部阅读锚点在暖机后变化不超过 1 点 |
| 视口上方冷行校准 | 修正错误的估算高度后，同一可见消息不被拖动 |
| 冷首屏上滚／点击 | 注入确定的冷行高度误差，用户滚轮或列表内按下鼠标均立即取消底部校准锁；布局稳定后不吸回底部 |
| 窗口变窄 | 长正文重新换行后，保留原消息及行内阅读位置，不沿用旧像素偏移 |
| 普通滚轮及尾帧 | 5 次 100 点输入只产生一次总计 500 点的位移，尾帧结束后阅读锚点不继续漂移 |
| 历史前插 | 通过真实数组事件插入跨日期消息，首帧及后续帧中同一消息的绘制位置变化不超过 1 点 |
| 小图对齐与命中 | 保留自然 16×12 尺寸、左右对齐；点击图像打开图片，槽内留白不打开 |
| GIF 源字节释放与格式变化 | 已有帧元数据时不重新探测缺失源字节；真实静态加载器不接管 `#frame`，base URI 仍能解码与上传 |
| 预览格式回落与错误槽 | PNG 后缀下的 GIF 必须实际画出帧；旧 GIF 元数据遇静态图必须清理并实际出图；过期链接保留专用文案与固定槽高 |
| GIF 后台任务 | 冷加载立即 Pending、完成唤醒；URI 去重、队列满可重试、forget／forget_all 后旧成功和错误结果不复活 |
| GIF 连续显示与缓存联动 | GPU 命中仍刷新动画像素缓存活跃状态；下一帧 Pending 时继续绘制可用帧，就绪后恢复播放；首次加载无画面时仍 Pending |
| GIF 显示与失效边界 | 不串用不同源或采样选项；真实错误和格式变化不被旧纹理遮蔽；清理源 URI 同时清理帧纹理，内嵌源可在像素缓存回收后重建 |
| GIF 原有容量规则 | 帧索引及帧时长正确；错误缓存有界；180 帧上限和活跃缓存宽限仍成立；保留画面不新增永久纹理缓存，陈旧离屏帧正常淘汰 |

几何测试每组合循环 90 帧，真实列表状态变化循环 60 次，普通滚轮还检查 40 个收尾帧。几何断言容差为 1 个 egui 逻辑点，不是物理像素。

底部锁用例同时检查输入立即解锁和布局稳定后不回吸，避免帧末“自然解锁”掩盖输入处理回归；窗口缩窄用例检查原阅读消息及行内位置，而不是只比较旧的绝对滚动偏移。

## 定向和重复验证

在仓库根目录执行：

```powershell
cargo test --release --locked app::chat::tests::scroll:: -- --test-threads=1
cargo test --release --locked app::chat::tests::image_preview:: -- --test-threads=1
cargo test --release --locked image_loader:: -- --test-threads=1
```

排查异步失效或不稳定回归时，可以重复验证实际模块路径：

```powershell
foreach ($round in 1..10) {
    foreach ($suite in @(
        'app::chat::tests::scroll::',
        'app::chat::tests::image_preview::',
        'image_loader::'
    )) {
        Write-Host "第 $round / 10 轮：$suite"
        cargo test --release --locked $suite -- --test-threads=1
        if ($LASTEXITCODE -ne 0) { throw "$suite 第 $round 轮失败" }
    }
}
```

## 人工复查

稳定预览槽的正文高为 240 点、引用高为 96 点，各加载状态保持一致。小图或横图可能留白，但不会被拉伸或放大；图像动作只命中实际图片区域。

在桌面环境中重点观察：

- 冷打开图片较多的会话时，立即上滚是否被拉回底部。
- 慢图片、GIF 加载和缓存重载时，阅读位置是否稳定；首次加载指示是否持续转动，弧长与亮度是否稳定，不周期性缩成点或闪灭。
- 多个 GIF 连续播放、滚出再滚回及缓存紧张时，已显示的动画是否闪回转圈；首次加载显示固定弧长的旋转指示，临时重建可以短暂保持可用帧，新帧就绪后应继续播放。
- 拉取旧消息的首帧是否跳动。
- 自己发送的小图是否右对齐。
- 窄窗下点击图像和留白区域，是否分别触发和不触发图片动作。

人工复查需要操作真实客户端，不随自动化测试执行；应使用获准访问的会话，并与自动化结果分开记录。
